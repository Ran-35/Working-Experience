# Elasticsearch (分布式搜索引擎)

## 1. 基本概念
一个分布式搜索引擎，基于 Apache Lucene 构建(一个可以快速搜索海量数据的数据库)。

## 2. 工作原理
### 2.1 倒排索引(核心)
传统数据库：根据ID找内容。
```text
ID=1  →  "小米手机很好用"
ID=2  →  "小米汽车性价比高"
ID=3  →  "小米平板性价比高"
```

Elasticsearch：根据内容找 ID。
```text
"小米"      →  [ID=1, ID=2, ID=3]
"手机"      →  [ID=1]
"性价比高"  →  [ID=2, ID=3]
```

### 2.2 分词
分析器会将长句子切分为一个个独立的词

```text
"小米手机很好用"
      ↓ 分词
["小米", "手机", "很好用"]
```

### 2.3 建立倒排表
系统会建立一套两级表。
第一级存储：词项 -- 文档ID列表
|词项 (Term)| 文档 ID 列表 (Posting List) | 
| ------ | --------- |
|机身 | List A |
|性能 | List B |
|打磨 | List C |
|显卡 | List D |
|强悍 | List E |

第二级存储：
若找 “机身” ————> List A 
| DOC ID | 词频 (TF) | 位置 (Position)| 偏移量（offsets）|
| ------ | --------- | ------------- | --------------- |
|1001|2|[1, 10]|[(2,4), (22,24)]|
|1002  |  4 | [1, 6, 12, 19]   | [(2,4), (12,14), ...]      |
|1005  |  1 | [3]              | [(6,8)]                    |
|1008  |  3 | [0, 7, 15]       | [(0,2), (14,16), (30,32)]  |

① 假设搜索 “显卡”  
② ES定位词项：显卡，找到文档 ID 列表 ListD  
③ 根据 ListD 结构的表 找到所在的文档 ID  
④ 根据 文档ID 找到词频、位置、偏移量计算关联分数： 

词频：
```text
score = tf × idf × norm

tf  (term frequency)  = 词在该文档中出现次数 → 越多越高分  
idf (inverse doc freq) = 词在多少文档中出现 → 越少文档出现越高分  
norm (field norm)      = 字段越短得分越高  


-----------------------
"机身" 在 Doc 1001 出现 2 次，Doc 1002 出现 4 次
"机身" 总共出现在 2 个文档中

Doc 1002 的 tf 更高 → 得分更高 → 排名靠前
```

位置：
```text
支持短语查询：
    搜索 "机身厚度"（phrase match）

    分词: ["机身", "厚度"]

    查倒排表:
    "机身" → Doc 1002, positions [1, 6, 12, 19]
    "厚度" → Doc 1002, positions [7]

    检查相邻:
    机身 pos=6, 厚度 pos=7  →  6 + 1 = 7 ✅ 相邻！命中！

    机身 pos=1, 厚度 pos=7  →  1 + 1 ≠ 7 ❌ 不相邻
    机身 pos=12, 厚度 pos=7 → 12 + 1 ≠ 7 ❌ 不相邻

    结论: "机身厚度" 只在 Doc 1002 中命中一次
---------------------------------------
支持 proximity 查询：
    搜索 "机身" 和 "厚度" 在 5 个词以内出现

    "机身" pos=6  "厚度" pos=7  →  距离 = 1 ✅ < 5

```

偏移量：
```text
支持高亮显示
    搜索 "机身"，命中 Doc 1002

    Offsets:
    (2, 4)   → 原文第 2~4 个字符是 "机身"
    (12, 14) → 原文第 12~14 个字符是 "机身"
    ...

    ES 直接用 offset 定位原文位置，包裹高亮标签:

    这款<em>机身</em>采用航空铝合金材质，<em>机身</em>厚度仅7.6mm，
    <em>机身</em>重量控制在185g，轻薄<em>机身</em>带来极致便携体验。
```

### 2.3 分片机制
一个分片就是一个完整的 Lucene 索引实例。
注：主分片数不能修改。
```text
索引 products
  │
  ├── Shard 0  →  独立的 Lucene 索引  →  自己的倒排索引
  ├── Shard 1  →  独立的 Lucene 索引  →  自己的倒排索引
  └── Shard 2  →  独立的 Lucene 索引  →  自己的倒排索引


每个分片内部：
    Shard 0 (独立的 Lucene 索引)
    ├── 倒排索引（只包含分配到这个分片的文档）
    ├── 正排存储（_source）
    ├── Doc Values（列存）
    ├── Segment 文件
    └── 完整的搜索能力
```

文档进入分片的路由算法：
```text
创建文档时未指定 routing:
  shard_num = hash(document._id) % primary_shards

示例（3个主分片）:
  hash("1001") % 3 = 1  →  Shard 1
  hash("1002") % 3 = 2  →  Shard 2
  hash("1003") % 3 = 0  →  Shard 0
  hash("1004") % 3 = 1  →  Shard 1
  hash("1005") % 3 = 2  →  Shard 2
  hash("1006") % 3 = 0  →  Shard 0
```
