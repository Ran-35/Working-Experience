# 自定义异常处理

统一异常处理是提升代码健壮性和前端交互体验的必经之路。它能让你告别满屏的 try-catch，并将错误信息标准化。

## 1. 核心原理
### 1.1 工作原理 
使用 @RestControllerAdvice 配合 @ExceptionHandler 来进行全局拦截。  

### 1.2 作用 
* **解耦**：业务代码不再掺杂大量的异常捕获逻辑。  
* **统一格式**：无论后端哪里出偏，返回给前端的 JSON 格式始终如一。  
* **安全**：防止堆栈信息泄露给用户，保护系统敏感信息。   

## 2 使用步骤
### 1️⃣响应结果
承载异常的容器
```java
@Data
public class Result<T> {
    private int code;      // 状态码
    private String message; // 提示信息
    private T data;        // 数据
}
```

### 2️⃣自定义异常
定义自己的异常(继承 RuntimeException)，后续使用：
```java
@Data
public class BearyException extends RuntimeException {
    private int code;

    public BearyException(int code, String message) {
        super(message);
        this.code = code;
    }
}
```
### 3️⃣自定义异常处理器
创建一个类，并打上 @RestControllerAdvice 注解。它就像一个“过滤器”，拦截所有 Controller 抛出的异常。
```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 1. 拦截自定义业务异常
    @ExceptionHandler(BearyException.class)
    public Result<?> handleBearyException(BearyException e) {
        return new Result<>(e.getCode(), e.getMessage());
    }

    // 2. 拦截参数校验异常 (Validation)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidationException(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getAllErrors().get(0).getDefaultMessage();
        return new Result<>(400, msg);
    }

    // 3. 兜底：拦截系统级异常
    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        // 记录日志，生产环境下隐藏具体堆栈
        return new Result<>(500, "服务器开小差了，请稍后再试");
    }
}
```

## 3 处理流程分析
1️⃣ **请求进入**：Controller 尝试处理请求。  
2️⃣ **触发异常**：业务逻辑或校验失败，throw 出一个异常。  
3️⃣ **查找匹配**：Spring 搜索被 @RestControllerAdvice 标记的类。  
4️⃣ **精准捕获**：根据异常类型匹配对应的 @ExceptionHandler。如果 BearyException 被抛出，优先进入特定处理方法；否则向上寻找直到 Exception.class。  
5️⃣ **返回响应**：将处理后的 Result 对象转为 JSON 返回给客户端。
