# Mybatis-Plus

MyBatis-Plus (简称 MP) 是一个 MyBatis 的增强工具，在 MyBatis 的基础上只做增强不做改变。它的核心理念是“为简化开发、提高效率而生”。

## 1. 基础应用
### 1.1 引入依赖
⚠️ 引入了 mybatis-plus-boot-starter 后，就不需要再引入原生的 mybatis-spring-boot-starter，否则可能导致冲突。

```xml
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-boot-starter</artifactId>
    <version>3.5.10</version> </dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
```

### 1.2 配置数据源
🏷️在 src/main/resources/application.yml 中配置数据源。
```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/your_db?useSSL=false&serverTimezone=GMT%2B8
    username: root
    password: yourpassword

mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl # 开启控制台 SQL 日志（开发推荐）
  mapper-locations: classpath*:/mapper/**/*.xml # 如果有自定义 XML 映射文件才需要配置
```

### 1.3 定义实体类
```java
@Data // Lombok 注解
@TableName("user") // 对应数据库中的 user 表
public class User {
    @TableId(type = IdType.AUTO) // 指定主键及自增策略
    private Long id;
    private String name;
    private Integer age;
    private String email;
}
```

### 1.4 定义Mapper接口
💡核心功能：只需继承 BaseMapper< T >，即可拥有完整的 CRUD 能力，无需编写任何 SQL。
```java
@Mapper // 标记为 Mapper 接口
public interface UserMapper extends BaseMapper<User> {
    // 所有的增删改查方法已自动继承
}
```

### 1.5 SpringBoot集成扫描
#### 1.5.1 @Mapper 方式
在每一个 Mapper 接口上都增加了 org.apache.ibatis.annotations.Mapper 注解，MyBatis 的 自动配置类（MybatisPlusAutoConfiguration）会自动扫描并注册这些带有注解的接口。

```java
@Mapper
public interface UserMapper extends BaseMapper<User> {
}
```

#### 1.5.2 @MapperScan 方式
在启动类上使用 @MapperScan("com.example.mapper")，那么在这个包下的所有接口都会被当作 Mapper 自动注册到 Spring 容器中。

```java
@SpringBootApplication
@MapperScan("com.example.demo.mapper") // 扫描你的 Mapper 路径
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

#### 1.5.3 对比
| **方案**   | **操作**                            | **效果**                         |
| -------- | --------------------------------- | ------------------------------ |
| **方案 A** | 在启动类上加 `@MapperScan` 注解，指定扫描的包路径。 | 省去每个接口写注解的麻烦，适合接口较多的项目，减少重复代码。 |
| **方案 B** | 每个接口加 `@Mapper` 注解。               | 适用于接口极少的情况，避免在启动类中配置，直接在接口上配置。 |

### 1.6 条件构造器
🏷️ MP 提供了强大的条件构造器，避免手写动态 SQL。
```java 
// 查询年龄大于 18 且名字包含 "Tom" 的用户
QueryWrapper<User> wrapper = new QueryWrapper<>();
wrapper.gt("age", 18)
       .like("name", "Tom");
       
List<User> list = userMapper.selectList(wrapper);
```

## 2. 高级应用
### 2.1 分页

#### 2.1.1 配置分页拦截器
```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 向拦截器中添加分页插件（指定数据库类型，如 MySQL）
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```
⚠️ 若Mybatis版本低于3.4.0，应使用PaginationInterceptor
```java 
@Configuration
public class MybatisPlusConfig {
    @Bean
    public PaginationInterceptor paginationInterceptor() {
        return new PaginationInterceptor();
    }
}
```

#### 2.1.2 使用分页
🎯 MP 提供了 IPage 接口和 Page 实现类来承载分页数据。
```java
@Service
public class UserService {

    @Autowired
    private UserMapper userMapper;

    public IPage<User> getUserPage(int pageNum, int pageSize) {
        // 1. 创建分页对象：参数为当前页码和每页显示数量
        Page<User> page = new Page<>(pageNum, pageSize);

        // 2. 执行分页查询
        // 可以传入 LambdaQueryWrapper 来添加筛选条件
        LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<>();
        queryWrapper.eq(User::getStatus, 1); 

        return userMapper.selectPage(page, queryWrapper);
    }
}
```
🏷️ Ipage返回的内容为：

| **属性**         | **说明**                  |
| -------------- | ----------------------- |
| `getRecords()` | 查询到的当前页数据列表（`List` 类型）。 |
| `getTotal()`   | 总记录数，表示数据表中所有记录的总数。     |
| `getCurrent()` | 当前页码，表示当前展示的页数。         |
| `getSize()`    | 每页显示条数，表示每页显示的记录数。      |
| `getPages()`   | 总页数，表示所有记录分成多少页。        |


#### 2.1.3 自定义分页
💡 只需在 Mapper 接口的方法中第一个参数传入 Page 对象即可。在 XML 中你不需要写 LIMIT 语句，MP 会自动在 SQL 末尾追加。

```java 
public interface UserMapper extends BaseMapper<User> {
    // 只要第一个参数是 IPage，MP 就会自动进行分页处理
    IPage<UserVo> selectCustomPage(IPage<UserVo> page, @Param("name") String name);
}
```
```xml
<select id="selectCustomPage" resultType="UserVo">
    SELECT * FROM user WHERE name = #{name}
</select>
```

### 2.2 动态表名
若想用一个实体类实现多张数据库表的操作，可以使用MP实现动态表名。

#### 2.2.1 配置动态表名拦截器
⚠️ 若Mybatis版本低于3.4.0，应使用PaginationInterceptor
```java
@Configuration
public class MybatisPlusConfig {
    // 定义 ThreadLocal 存储动态表名
    public static ThreadLocal<String> CUSTOM_TABLE_NAME = new ThreadLocal<>();

    @Bean
    @Order(0)
    public PaginationInterceptor paginationInterceptor() {
        PaginationInterceptor paginationInterceptor = new PaginationInterceptor();

        // --- 动态表名配置开始 ---
        List<ISqlParser> sqlParserList = new ArrayList<>();
        DynamicTableNameParser tableNameParser = new DynamicTableNameParser();

        tableNameParser.setTableNameHandlerMap(new HashMap<String, ITableNameHandler>(2) {{
            // 当 SQL 中识别到 "user" 时，替换为 ThreadLocal 中的值
            put("user", (metaObject, sql, tableName) -> {
                String dynamicName = CUSTOM_TABLE_NAME.get();
                return dynamicName != null ? dynamicName : tableName;
            });
        }});

        sqlParserList.add(tableNameParser);
        paginationInterceptor.setSqlParserList(sqlParserList);
        // --- 动态表名配置结束 ---
        return paginationInterceptor;
    }
}
```

#### 2.2.2 使用 ThreadLocal 传递变量
💡 为了保证线程安全，通常使用 ThreadLocal 来在 Service 层和拦截器之间传递动态表名标识。

```java 
@Configuration
public class MybatisPlusConfig {
    // 使用 ThreadLocal 传递变量
    private static final ThreadLocal<String> TABLE_NAME_HOLDER = new ThreadLocal<>();

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        
        // 创建动态表名插件
        DynamicTableNameInnerInterceptor dynamicTableNameInnerInterceptor = new DynamicTableNameInnerInterceptor();
        
        dynamicTableNameInnerInterceptor.setTableNameHandler((sql, tableName) -> {
            // tableName 是原始表名（实体类上 @TableName 定义的名称）
            // 我们可以通过 ThreadLocal 获取运行时传递的“后缀”或“特定名称”
            String dynamicSuffix = TableNameContext.get(); 
            
            if ("user".equals(tableName) && dynamicSuffix != null) {
                return tableName + "_" + dynamicSuffix; // 返回实际执行的表名：user_2024
            }
            return tableName; // 否则返回原表名
        });

        // 将插件添加到主拦截器（建议放在分页插件之前）
        interceptor.addInnerInterceptor(dynamicTableNameInnerInterceptor);
        return interceptor;
    }
}

```
#### 2.2.3 使用动态表名
```java 
@Service
public class UserService {
    @Autowired
    private UserMapper userMapper;

    public List<User> getUserFromSpecificTable(String year) {
        try {
            // 设置当前线程要查询的表后缀
            MybatisPlusConfig.TABLE_NAME_HOLDER.set(year);
            
            // 执行查询，此时 SQL 会自动变为：SELECT * FROM user_2024
            return userMapper.selectList(null);
        } finally {
            // 必须清理，避免对后续线程产生干扰
            TableNameContext.remove();
        }
    }
}
```
