# 获取外部 URL 数据

## 1. RestTemplate(经典同步方式)
👉 Spring 3.0 引入的同步 HTTP 客户端。它采用了模板模式，将复杂的 HTTP 连接、序列化等细节封装起来。

### 1.1 工作原理
🧠 基于“每个请求一个线程（Thread-per-request）”模型。当发起请求时，当前线程会阻塞，直到收到响应。

### 1.2 优缺点
✅ 优点：直观，易于理解和调试；在传统单体应用或并发量不高的场景下性能稳定。  
❌ 缺点：高并发场景下，大量阻塞线程会消耗系统资源，导致吞吐量受限。

### 1.3 使用方法
#### ① 编写配置类  
编写配置类，注册 RestTemplate Bean
```java
@Configuration
public class RestConfig {

    @Bean("myRestTemplate") // 自定义名称，为了防止其他的ResTemplate冲突
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}

```
#### ② 使用RestTemplate执行方法
1. getForObject()：直接返回响应体数据。
```java
public <T> T getForObject(URI url, Class<T> responseType)
// uriVariables会直接拼在url后面
public <T> T getForObject(String url, Class<T> responseType, Object... uriVariables)
public <T> T getForObject(String url, Class<T> responseType, Map<String, ?> uriVariables)
```
```java
public class RequestTest {
    @Resource(name = "myRestTemplate")  // 要与定义的名称一致
    private RestTemplate restTemplate;

    @Test
    public void getData() {
        // String.class 是要输出的类型(RestTemplate 最强大的地方：自动化对象映射)
        String data =restTemplate.getForObject("http://172.18.187.138/oauth-client/cookie/manage/get", String.class);   

        // 若要在url上补充请求参数(以url参数补充)
        String data =restTemplate.getForObject("http://172.18.187.138/oauth-client/cookie/manage/get/{id}", String.class, 3238273139);   
        log.info(data);

        // 以请求参数的形式补充
        String url = "http://api.example.com/data?date={date}&name={name}";
        
        // 方法一
        Map<String, String> params = new HashMap<>();
        params.put("date", date);
        params.put("name", name);

        String data = restTemplate.getForObject(url, String.class, params);

        // 方法二
        String baseUrl = "http://api.example.com/data?date={date}&name={name}";
        String url = UriComponentsBuilder.fromHttpUrl(baseUrl)
                .queryParam("date", date)
                .queryParam("name", name)
                .build()
                .toUriString();
        String data = restTemplate.getForObject(url, String.class, params);

        
        // 方法三
        String url = "http://api.example.com/data?date={1}&name={2}";

        // 参数 1 填入 {1}, 参数 2 填入 {2}
        return restTemplate.getForObject(url, String.class, "2024-10-01", "张三");
    }
}

```

2. getForEntity(): 返回 ResponseEntity，包含状态码、响应头等
```java
// 1. 无参数请求

// 2. 带占位符参数（数组形式）
public <T> ResponseEntity<T> getForEntity(String url, Class<T> responseType, Object... uriVariables);
// 3. 带占位符参数（Map形式）
public <T> ResponseEntity<T> getForEntity(String url, Class<T> responseType, Map<String, ?> uriVariables);
```
```java
public class RequestTest {

    private RestTemplate restTemplate;

    @Test
    public void getData() {
        ResponseEntity<String> forEntity = restTemplate.getForEntity("http://172.18.187.138/oauth-client/cookie/manage/get", String.class);
        log.info("statusCode: {}", forEntity.getStatusCode());
        log.info("headers: {}", forEntity.getHeaders());
        log.info("body: {}", forEntity.getBody());

        // 其他用法与getForObject一致
    }
}

```

3. postForObject(): 发送数据并返回结果。
```java
User newUser = new User("John", "New York");
// 第二个参数是 RequestBody，RestTemplate 会自动将其转为 JSON
User savedUser = restTemplate.postForObject("http://api.example.com/users", newUser, User.class);
```

4. exchange()：可以支持所有的 HTTP 动词（包括 DELETE, PUT, PATCH），并且可以自定义 请求头 (Headers)。
```java
HttpHeaders headers = new HttpHeaders();
headers.set("Authorization", "Bearer your_token");
headers.setContentType(MediaType.APPLICATION_JSON);

HttpEntity<User> requestEntity = new HttpEntity<>(newUser, headers);

// 使用 exchange 发送请求
ResponseEntity<String> response = restTemplate.exchange(
    "http://api.example.com/users/1", // 请求url
    HttpMethod.PUT,                   // 请求类型
    requestEntity,                    // 请求体
    String.class                      // 响应头类型
);
```
#### ③ 注意事项
##### 处理异常
RestTemplate 默认在收到 4xx 或 5xx 状态码时会抛出异常, 此时需要通过自定义错误处理逻辑解决。
```java
restTemplate.setErrorHandler(new DefaultResponseErrorHandler() {
    @Override
    public void handleError(ClientHttpResponse response) throws IOException {
        // 在这里自定义错误处理逻辑，或者直接忽略错误继续读取返回内容
    }
});
(2) 
```
##### 泛型结果返回
如果需要返回一个 List，直接传 List.class 会丢失泛型信息。这时需要使用 ParameterizedTypeReference：
```java
ResponseEntity<List<User>> response = restTemplate.exchange(
    "http://api.example.com/users",
    HttpMethod.GET,
    null,
    new ParameterizedTypeReference<List<User>>() {}
);
List<User> users = response.getBody();
```

## 2. WebClient(现代响应式方式)
👉 Spring 5.0 中随 Spring WebFlux 引入的，旨在取代 RestTemplate。

### 2.1 工作原理
🧠 基于响应式编程（Reactor 库）。它使用少量的线程（通常是 CPU 核心数）来处理大量的并发请求。请求发出后，线程会立即释放去处理其他任务，当响应回来时，通过回调机制通知处理。

### 2.2 优缺点
✅ 优点：  
    (1)非阻塞： 极高的资源利用率，适合高并发、流式数据传输；  
    (2)支持同步与异步： 既可以像 RestTemplate 一样 .block() 等待结果，也可以异步处理；  
    (3)功能更强： 支持 HTTP/2、WebSocket。  
❌ 缺点：学习曲线陡峭;代码调试相对复杂。

### 2.3 使用方法
#### ① 添加依赖
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>
```
#### ② 编写配置类
```java
@Configuration
public class WebClientConfig {
    @Bean
    public WebClient webClient() {
        return WebClient.builder()
                .baseUrl("http://api.example.com") // 设置基础URL
                .defaultHeader(HttpHeaders.CONTENT_TYPE, MediaType.APPLICATION_JSON_VALUE)
                // 注册自定义过滤器
                .filter(addCustomHeader())
                .filter(logRequest())
                .build();
    }

    // 示例 1：统一添加请求头（如 Auth Token）
    private ExchangeFilterFunction addCustomHeader() {
        return (request, next) -> {
            ClientRequest filteredRequest = ClientRequest.from(request)
                    .header("Authorization", "Bearer my-secret-token")
                    .header("Source-App", "Spring-Boot-Client")
                    .build();
            return next.exchange(filteredRequest);
        };
    }

    // 示例 2：统一打印请求日志
    private ExchangeFilterFunction logRequest() {
        return (request, next) -> {
            System.out.println("【WebClient请求】Method: " + request.method() + " URL: " + request.url());
            return next.exchange(request);
        };
    }
}
```
#### ③ 发送请求
(1) get请求
```java
@Configuration

        return WebClient.builder()
                .baseUrl("http://api.example.com") // 设置基础URL
```

(2)Post请求


```java
        .uri("/data")

```
#### ④ 异常处理
```java
public Mono<String> getDataWithDetailError() {
    return webClient.get()
            .uri("/api/data")
            .retrieve()
            .onStatus(HttpStatus::is4xxClientError, response -> {
                return Mono.error(new RuntimeException("客户端错误了！"));
            })
            .onStatus(HttpStatus::is5xxServerError, response -> {
                return Mono.error(new RuntimeException("服务器挂了！"));
            })
            .bodyToMono(String.class);
}
```

## 3. OpenFeign(声明式调用)
👉 由 Netflix 开发，后集成到 Spring Cloud 中。它并不是底层的 HTTP 发送器，而是一个封装器。

### 3.1 工作原理
🧠 定义一个 Java 接口并添加注解，Feign 会在运行时生成代理对象。它底层通常默认使用 JDK 原生的 HttpURLConnection，但可以轻松切换为 OkHttp 或 Apache HttpClient。
### 3.2 优缺点
✅ 优点：  
(1)代码最优雅：像调用本地方法一样调用远程接口，完全解耦；  
(2)生态集成： 天然集成负载均衡（LoadBalancer）和熔断器（Sentinel/Resilience4j）。      
❌ 缺点：灵活性略逊于前两者，处理复杂的动态 URL 或特殊的 HTTP 操作时较为繁琐。
### 3.3 使用方法
#### ① 添加依赖
```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
```
#### ② 客户端启用Feign
```java
@SpringBootApplication
@EnableFeignClients // 开启 Feign 扫描
public class MyApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }
}
```
#### ③ 定义 Feign 客户端
```java
// name: 给这个客户端取个名
// url: 目标服务的地址
@FeignClient(name = "cookieClient", url = "http://172.18.187.138")
public interface CookieClient {

    // 这里的路径对应具体的接口位置
    @GetMapping("/oauth-client/cookie/manage/get")
    String getCookieData();

    // 也可以带参数
    @GetMapping("/oauth-client/cookie/search")
    String searchCookie(@RequestParam("name") String name);
}
```
#### ④ 使用 Feign 
```java
@Service
public class BusinessService {
    @Resource
    private CookieClient cookieClient;

    public void doBusiness() {
        // 像调用本地方法一样简单！
        String result = cookieClient.getCookieData();
        System.out.println(result);
    }
}
```
#### ⑤ 自定义 Feign 的方法
```java
@Configuration
public class JsApiFeignConfig {
    @Resource
    private HttpMessageConverters messageConverters;

    // 后置过滤器，在执行后执行操作
    @Bean
    public Decoder feignDecoder() {
        Decoder delegate = new ResponseEntityDecoder(new OptionalDecoder(new SpringDecoder(() -> messageConverters)));

        return (response, type) -> {
            // 获取响应内容必须在 decode 之前，否则流会被关闭
            byte[] bodyData = null;
            if (response.body() != null) {
                bodyData = feign.Util.toByteArray(response.body().asInputStream());
            }

            // 用缓存的数据重建 Response 对象，否则 delegate 无法解析
            Response newResponse = response.toBuilder().body(bodyData).build();

            // 1. 执行原有的解码逻辑
            Object result = delegate.decode(newResponse, type);

            // 2. 统一操作：现在你可以安全地使用 bodyData 或其他信息
            System.out.println("请求执行成功！URL: " + response.request().url());
            System.out.println("状态码: " + response.status());

            if (bodyData != null) {
                String responseMessage = new String(bodyData, StandardCharsets.UTF_8);
                 System.out.println("响应消息: " + responseMessage);
            }

            return result;
        };
    }

    // 前置过滤器，在所有Feign执行前执行此操作
    @Bean
    public RequestInterceptor requestInterceptor() {
        return requestTemplate -> {
            // 1. 设置通用的 Cookie
            //requestTemplate.header("Cookie", Constant.JSPEC_COOKIE);
            requestTemplate.header("Cookie", CookieConfigManage.getInstance().getCookie());

            // 2. 获取当前请求的 URL 路径
            String url = requestTemplate.url();
            // 3. 获取当前请求的参数(url中)
            Map<String, Collection<String>> queries = requestTemplate.queries();
            // 4. 获取当前请求的参数(body中)
            byte[] bodyBytes = requestTemplate.body();
            JsonNode jsonNode = null;
            if (bodyBytes != null) {
                String bodyJson = new String(bodyBytes, StandardCharsets.UTF_8);
                try {
                    jsonNode = new ObjectMapper().readTree(bodyJson);
                } catch (Exception e) {
                    throw new RenException(500, "Body 解析失败");
                }
            }
            switch (url) {
                case "/px-spotgoods-province/dayClearingResult/queryTableXrdOnlyJiesuan":
                    requestTemplate.header("Currentroute", "/pxf-spotgoods-province-extranet/afterDiscloseInformation/xrdClearingResultOnlyJiesuan/DayClearingResult?date=" + System.currentTimeMillis());
                    break;
                case "/px-spotgoods-province/curClearingResult/queryTableXrdOnlyJiesuan":
                    requestTemplate.header("Currentroute", "/pxf-spotgoods-province-extranet/afterDiscloseInformation/xrdClearingResultOnlyJiesuan/CurClearingResult?date=" + System.currentTimeMillis());
                    break;
                case "/px-settlement-infpubquery/tableCurve/queryBranchDispatchCurveData":
                    String infoCode = "";
                    assert jsonNode != null;
                    if (jsonNode.has("infoCode")) {
                        infoCode = jsonNode.get("infoCode").asText();
                    }
                    if (infoCode.contains("sn_xhpl_dqxtfhyc")){
                        requestTemplate.header("Currentroute", "/pxf-settlement-outnetpub/InformationDisclosureRouter/nintySixPointsUrl?infoCode=sn_xhpl_dqxtfhyc_7_2&date=" + System.currentTimeMillis());
                        break;
                    } else if (infoCode.contains("sn_xhpl_dqxnyfdnl")) {
                        requestTemplate.header("Currentroute", "/pxf-settlement-outnetpub/InformationDisclosureRouter/nintySixPointsUrl?infoCode=sn_xhpl_dqxnyfdnl_7_3&date=" + System.currentTimeMillis());
                        break;
                    }

            }
        };
    }

}
```

## 三者对比
| 特性            | RestTemplate | WebClient          | OpenFeign                |
| ------------- | ------------ | ------------------ | ------------------------ |
| **编程模型**      | 同步 / 阻塞      | 异步 + 同步 / 非阻塞      | 同步（通常）                   |
| **设计风格**      | 模板模式         | 链式 / 流式 API        | 声明式（接口注解）                |
| **底层依赖**      | Servlet 堆栈   | Reactive 堆栈（Netty） | 可配置（OkHttp / HttpClient） |
| **Spring 版本** | Spring 3.0+  | Spring 5.0+        | Spring Cloud             |
| **适用场景**      | 传统单体、低并发     | 高并发、响应式系统、Gateway  | 微服务架构、内部服务调用             |
