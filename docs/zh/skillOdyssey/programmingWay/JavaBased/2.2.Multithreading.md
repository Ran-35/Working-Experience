# 线程、多线程（Thread）

多线程可以通过同时执行多个线程，从而充分利用多核 CPU 的性能来提高程序的并行性和性能。线程是程序执行的基本单元，而进程包含多个线程。在 Java 中，有多种方式实现线程，可以根据实际需求选择最合适的方式。


## 1. 核心概念：进程 vs 线程
### 1.1 基本概念
* **线程 (Thread)**：CPU 调度的最小单位，是进程内的执行单元。一个进程可以包含多个线程，它们共享该进程的内存资源（堆和方法区），但拥有独立的栈。  
* **进程 (Process)**：操作系统分配资源的最小单位，进程内的多个线程构成了一个执行单元。

### 1.2 线程生命周期

**① New (新建)**：创建了线程对象，还没调用`start()`，尚未启动。 

**② Runnable (就绪/运行)**：在 JVM 中执行，可能正在等待系统资源（如 CPU）。  

**③ Blocked (阻塞)**：等待获取监视器锁（`synchronized`）（线程由于某些条件（如 I/O 操作）被阻塞，等待某个条件满足）。 

**④ Wating(等待)**：无限期等待另一个线程执行特定操作（`wait`、`join`）。  

**⑤ Timed_Wating(超时等待)**：在指定时间内等待（`sleep(ms)`、`wait(ms)`）。  

**⑥ Terminated (终止)**：线程执行完毕。  

⚠️ **线程创建**：java创建线程只有一种方式new Thread().start()。不管其他哪种多线程的创建方式，最终都是依赖该方式。 

⚠️ **线程运行**：new一个Thread后，调用start()方法会自动执行run方法。而直接执行run()方法会将其作为一个普通方法执行而非多线程。   

⚠️ **线程等待**：Thread.sleep() 和 Object.wait()
| 特性    | Thread.sleep()          | Object.wait()                  |
| ----- | ----------------------- | ------------------------------ |
| 所属类   | java.lang.Thread (静态方法) | java.lang.Object (实例方法)        |
| 锁资源释放 | 不释放锁，抱着锁睡觉              | 释放锁，交出执行权供他人竞争                 |
| 使用限制  | 可以在任何地方调用               | 必须在 synchronized 代码块内调用        |
| 唤醒条件  | 指定时间结束后自动唤醒             | 需等待 notify() / notifyAll() 或超时 |
| 线程状态  | TIMED_WAITING           | WAITING 或 TIMED_WAITING        |
| 主要用途  | 暂停执行、轮询等待               | 线程间通信、生产者消费者模型                 |
| 锁的行为  | “占着茅坑不拉屎”      | “先出来等通知”                 |
| 何时使用  | 只是想让当前线程慢点执行 或者 做简单的定时模拟     |需要多个线程协作             |

### 1.3 线程上下文切换
线程上下文切换（Thread Context Switch）：是多任务操作系统的核心机制。它允许 CPU 在多个线程之间快速切换，从而营造出多个程序“同时运行”的假象。

#### 1.3.1 线程上下文
上下文是指 CPU 在执行某个线程时所依赖的所有环境信息。  
主要包含以下内容：  
① 寄存器状态： 包括通用寄存器、程序计数器（PC，指向下一条指令）、栈指针（SP）等。  
② 内核栈： 每个线程在内核态执行时都有自己的栈。  
③ 用户栈： 线程在用户态执行时的局部变量和函数调用信息。

#### 1.3.2 切换的基本流程
1️⃣ 保存上下文： 将线程 A 当前的寄存器值、程序计数器等信息保存到该线程的控制块（TCB）或内核栈中。  
2️⃣ 切换调度： 操作系统调度器（Scheduler）根据算法（如时间片轮转或优先级）选定下一个要运行的线程 B。  
3️⃣ 恢复上下文： 从线程 B 的控制块中读取之前保存的状态，载入到 CPU 的寄存器中。  
4️⃣ 跳转执行： 根据恢复的程序计数器，跳转到线程 B 上次停止的地方继续执行。

#### 1.3.3 触发切换的场景
* 时间片用完： 操作系统为了保证公平，强制剥夺高耗时线程的执行权。  
* 主动挂起： 线程调用了 sleep()、wait() 或 yield()。  
* 阻塞等待： 线程在等待 I/O 读写、获取锁（Lock）或网络响应。  
* 硬件中断： 外设（如硬盘、网卡）完成任务发出中断信号，系统被迫切换到中断处理程序。

#### 1.3.4 注意事项
⚠️ 频繁切换会导致系统性能下降，主要原因包括：  

 **①** 保存和恢复寄存器、更新内核数据结构（调度链表）所需的 CPU 指令耗时。  
 **② 缓存失效 (Cache Miss)**： 线程 A 的数据原本在 CPU L1/L2 缓存中，切换到线程 B 后，B 需要重新从内存读取数据，导致缓存命中率暴跌。  
 **③ TLB 刷新**： 如果切换涉及到不同进程的线程，页表缓存（TLB）会被清空，导致虚拟地址转换变慢。

 🧠 减少上下文切换：

 **① 无锁编程 (Lock-free)**： 使用 CAS（Compare and Swap）算法代替传统的互斥锁，避免线程因为竞争锁而进入阻塞状态。  
 **② 协程 (Coroutines)**： 在用户态实现切换，不需要内核参与，开销极小（如 Go 语言的 Goroutine）。  
 **③ 合理设置线程数**： 线程数并非越多越好。通常 CPU 密集型任务建议线程数等于 CPU 核心数；I/O 密集型任务可适当增加，但需通过压测找平衡点。  
 **④ 使用自旋锁 (Spinlock)**： 如果预估锁占用的时间极短，让线程在循环中“等一下”而不是直接挂起，可以省去两次上下文切换。





## 2. 多线程
### 2.1 基本概念
#### 2.1.1 并发 VS 并行
* `并发`：两个及两个以上的作业在同一 **时间段** 内执行。
* `并行`：两个及两个以上的作业在同一 **时刻** 执行。

#### 2.1.2 同步 VS 异步
* `同步`：发出一个调用之后，在没有得到结果之前， 该调用就不可以返回，一直等待。
* `异步`：调用在发出之后，不用等待返回结果，该调用直接返回。

### 2.2 线程死锁

两个或多个线程在执行过程中，因争夺资源而造成的一种互相等待的现象，若无外力作用，它们都将无法继续推进。

#### 2.2.1 四个必要条件
只有当以下四个条件同时满足时，才会发生死锁。

**① 互斥条件（Mutual Exclusion）**：资源是独占的，同一时刻只能被一个线程占用（如 synchronized 锁）。  
**② 请求与保持条件（Hold and Wait）**：线程已经持有了至少一个资源，但又提出了新的资源请求，而该资源已被其他线程占用。此时请求线程阻塞，但对自己已获得的资源保持不放。  
**③ 不剥夺条件（No Preemption）**：线程已获得的资源在未使用完之前，不能被其他线程强行剥夺，只能由自己释放。  
**④ 循环等待条件（Circular Wait）**：存在一个线程服务的循环链。比如：线程 A 等待线程 B 占有的资源，线程 B 等待线程 C 占有的资源，线程 C 等待线程 A 占有的资源。  

**示例**：  
🎯 现象：控制台打印出“尝试锁定...”后便再无动静，程序永远不会结束。
```java
public class DeadlockDemo {
    private static Object resourceA = new Object();
    private static Object resourceB = new Object();

    public static void main(String[] args) {
        // 线程 1：锁定 A，试图锁定 B
        new Thread(() -> {
            synchronized (resourceA) {
                System.out.println("线程 1: 已锁定 A");
                try { Thread.sleep(100); } catch (Exception e) {} // 确保线程 2 锁定 B
                
                System.out.println("线程 1: 尝试锁定 B...");
                synchronized (resourceB) {
                    System.out.println("线程 1: 成功锁定 B");
                }
            }
        }).start();

        // 线程 2：锁定 B，试图锁定 A
        new Thread(() -> {
            synchronized (resourceB) {
                System.out.println("线程 2: 已锁定 B");
                try { Thread.sleep(100); } catch (Exception e) {}
                
                System.out.println("线程 2: 尝试锁定 A...");
                synchronized (resourceA) {
                    System.out.println("线程 2: 成功锁定 A");
                }
            }
        }).start();
    }
}
```

#### 2.2.3 预防死锁
破坏死锁的四个必要条件之一，即可解决问题：

① 破坏 **循环等待** ：固定加锁顺序（最常用）  
让所有线程都按照相同的顺序获取资源。比如，无论哪个线程，都必须先锁 A 再锁 B。
```java
public class DeadlockDemo {
    private static Object resourceA = new Object();
    private static Object resourceB = new Object();

    public static void main(String[] args) {
        // 线程 1：锁定 A，试图锁定 B
        new Thread(() -> {
            synchronized (resourceA) {
                System.out.println("线程 1: 已锁定 A");
                try { Thread.sleep(100); } catch (Exception e) {} // 确保线程 2 锁定 B
                
                System.out.println("线程 1: 尝试锁定 B...");
                synchronized (resourceB) {
                    System.out.println("线程 1: 成功锁定 B");
                }
            }
        }).start();

        // 线程 2：锁定 A，试图锁定 B(破坏 循环等待 条件)
        new Thread(() -> {
            synchronized (resourceA) { // 改变了锁的顺序：先锁定 A
                System.out.println("线程 2: 已锁定 A");
                try { Thread.sleep(100); } catch (Exception e) {}

                System.out.println("线程 2: 尝试锁定 B...");
                synchronized (resourceB) {
                    System.out.println("线程 2: 成功锁定 B");
                }
            }
        }).start();
    }
}

```

② 破坏 **请求与保持** ：一次性申请所有资源
不在持有锁的时候去请求新锁，而是尝试一次性获取所有需要的锁。
```java 
public class DeadlockDemo {
    private static Lock resourceA = new ReentrantLock();
    private static Lock resourceB = new ReentrantLock();

    public static void main(String[] args) {
        // 线程 1：尝试一次性锁定 A 和 B
        new Thread(() -> {
            try {
                if (resourceA.tryLock() && resourceB.tryLock()) {
                    System.out.println("线程 1: 成功锁定 A 和 B");
                    try {
                        // 线程 1 执行任务
                        Thread.sleep(100);
                    } finally {
                        resourceA.unlock();
                        resourceB.unlock();
                    }
                } else {
                    System.out.println("线程 1: 未能获取到所需资源，重新尝试");
                }
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }).start();

        // 线程 2：尝试一次性锁定 A 和 B
        new Thread(() -> {
            try {
                if (resourceA.tryLock() && resourceB.tryLock()) {
                    System.out.println("线程 2: 成功锁定 A 和 B");
                    try {
                        // 线程 2 执行任务
                        Thread.sleep(100);
                    } finally {
                        resourceA.unlock();
                        resourceB.unlock();
                    }
                } else {
                    System.out.println("线程 2: 未能获取到所需资源，重新尝试");
                }
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }).start();
    }
}

```
③ 破坏 **不剥夺** ：使用 tryLock()
使用 ReentrantLock 的 tryLock(time, unit)。如果尝试获取锁超时，就主动释放已经持有的锁，退回并重试。
```java
public class DeadlockDemo {
    private static Lock resourceA = new ReentrantLock();
    private static Lock resourceB = new ReentrantLock();

    public static void main(String[] args) {
        // 线程 1：尝试获取资源 A 和 B，如果超时则释放已有资源
        new Thread(() -> {
            try {
                boolean gotA = resourceA.tryLock();
                if (gotA) {
                    System.out.println("线程 1: 成功锁定 A");
                    try {
                        // 等待足够长时间模拟获取资源 B
                        boolean gotB = resourceB.tryLock();
                        if (gotB) {
                            System.out.println("线程 1: 成功锁定 B");
                            // 线程 1 执行任务
                            Thread.sleep(100);
                        } else {
                            System.out.println("线程 1: 未能获取到 B，释放 A 并重新尝试");
                            resourceA.unlock(); // 释放 A
                            Thread.sleep(100); // 稍作休息
                        }
                    } finally {
                        if (resourceB.isHeldByCurrentThread()) {
                            resourceB.unlock();
                        }
                    }
                }
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }).start();

        // 线程 2：尝试获取资源 A 和 B，如果超时则释放已有资源
        new Thread(() -> {
            try {
                boolean gotA = resourceA.tryLock();
                if (gotA) {
                    System.out.println("线程 2: 成功锁定 A");
                    try {
                        // 等待足够长时间模拟获取资源 B
                        boolean gotB = resourceB.tryLock();
                        if (gotB) {
                            System.out.println("线程 2: 成功锁定 B");
                            // 线程 2 执行任务
                            Thread.sleep(100);
                        } else {
                            System.out.println("线程 2: 未能获取到 B，释放 A 并重新尝试");
                            resourceA.unlock(); // 释放 A
                            Thread.sleep(100); // 稍作休息
                        }
                    } finally {
                        if (resourceB.isHeldByCurrentThread()) {
                            resourceB.unlock();
                        }
                    }
                }
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }).start();
    }
}

```






### 2.3 ThreadLocal
✅Java 提供的一种特殊变量，它的核心思想是：为每个线程提供一个独立的变量副本。

**synchronized**：是为了让多个线程排队访问共享变量；  
**ThreadLocal**：是通过 空间换时间 ，让每个线程只访问自己的私有副本，从而彻底避免了竞争。

#### 2.3.1 底层原理
**① 数据存放在 Thread 中**：每个 Thread 对象内部都有一个名为 threadLocals 的成员变量，它的类型是 ThreadLocalMap。  
**② ThreadLocalMap**：这是一个类似于 HashMap 的结构，它的 Key 是 ThreadLocal 对象本身，Value 是我们要存的值。  
**③ 弱引用（WeakReference）**：ThreadLocalMap 中的 Entry 对 Key 的引用是弱引用，而对 Value 的引用是强引用。

⚠️ 弱引用 VS 强引用
| 特性         | 强引用（Strong Reference） | 弱引用（Weak Reference）      |
| ---------- | --------------------- | ------------------------ |
| **对象生命周期** | 只要强引用存在，对象就不会被垃圾回收    | 对象只要没有强引用，即使有弱引用也会被回收    |
| **垃圾回收行为** | 对象不会被垃圾回收器回收          | 对象会在下次垃圾回收时被回收，即使有弱引用存在  |
| **典型应用**   | 常规对象引用，程序中大多数对象都使用强引用 | 缓存、对象池、监听器等需要对象可随时被回收的场景 |
| **常见类**    | 普通对象引用                | `WeakReference<T>`       |

#### 2.3.2 内存泄漏
由于 ThreadLocalMap 的 Key 是弱引用，如果 ThreadLocal 对象没有外部强引用指向它，在 GC 时 Key 会被回收，此时 Key 变成 null。

但是，Value 是强引用。只要线程不销毁（比如在线程池中，线程会被复用），这个 null 对应的 Value 就会一直存在于内存中，无法被回收，从而导致内存泄漏。

💡**内存泄漏**：程序在运行过程中未能正确释放已经不再使用的内存，导致这些内存无法被重新利用，最终可能耗尽系统的内存资源，导致程序运行效率下降，甚至崩溃。

🧠**解决办法**：在使用完 ThreadLocal 后，务必调用 remove() 方法。
```java 
try {
    threadLocal.set(data);
    // 业务逻辑
} finally {
    threadLocal.remove(); // 显式清理，防止内存泄漏
}
```

#### 2.3.3 跨线程传递 ThreadLocal 的值
##### ① InheritableThreadLocal（JDK 自带）
✅适用于父子线程（即在当前线程中 new Thread()）的场景。

**原理**： 当子线程被创建时，它会拷贝父线程中 inheritableThreadLocals 变量池里的所有数据。  
**局限性**： 仅在创建线程时拷贝。在线程池环境下，线程是被复用的，不会重新创建，因此无法获取到提交任务那一刻的新值。
```java
ThreadLocal<String> threadLocal = new InheritableThreadLocal<>();
threadLocal.set("父线程的值");

new Thread(() -> {
    System.out.println("子线程获取: " + threadLocal.get()); // 可以获取到
}).start();
```
##### ② TransmittableThreadLocal(TTL 阿里巴巴开源，最推荐)
✅解决了线程池复用线程导致 InheritableThreadLocal 值过时的问题。

**原理**： 它通过“捕获”和“重放”机制，在任务提交时抓取当前线程的值，在任务执行前注入到执行线程中，执行完后再恢复。  

1️⃣ 使用 TransmittableThreadLocal 声明变量。
2️⃣ 使用 TtlExecutors 修饰线程池。
```java 
// 1. 定义
TransmittableThreadLocal<String> context = new TransmittableThreadLocal<>();
context.set("我的信息");

// 2. 修饰线程池
Executor executor = TtlExecutors.getTtlExecutor(existingExecutor);

executor.execute(() -> {
    System.out.println(context.get()); // 即使是线程池复用，也能拿到最新值
});
```

##### ③ 手动显式传递（最原始但可靠）
在提交任务前通过构造函数或闭包将值传入，执行时再手动 set。
```java
String value = threadLocal.get(); // 1. 主线程取值
executor.execute(() -> {
    try {
        threadLocal.set(value);   // 2. 子线程设值
        // 业务逻辑...
    } finally {
        threadLocal.remove();     // 3. 必须清除，防止内存泄漏和污染
    }
});
```
#### 2.3.4 使用场景
📅**压测流量标记**： 在压测场景中，使用 ThreadLocal 存储压测标记，用于区分压测流量和真实流量。如果标记丢失，可能导致压测流量被错误地当成线上流量处理。  
📅**上下文传递**：在分布式系统中，传递链路追踪信息（如 Trace ID）或用户上下文信息。

### 2.4 实现多线程的几种方式
#### 2.4.1 继承 `Thread` 类
✅自定义一个类，继承 `Thread` 并重写 `run()` 方法，将线程任务放在 `run()` 方法中。  

##### ① 使用步骤
1️⃣ 创建一个继承 `Thread` 类的线程类。  
2️⃣ 重写 `run()` 方法定义线程任务。  
3️⃣ 创建线程对象，并启动线程。  
4️⃣ 调用start() 方法启动线程。  
5️⃣ 创建多个线程对象，并启动线程。 


 ```java 
 // 1. 创建线程类，继承Thread类
 class Mythread extends Thread {
    // 2. 重新run方法，编写线程要执行的任务
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName());
            System.out.println(Thread.currentThread().getState());
            System.out.println(Thread.currentThread().getId());
            System.out.println("i = " + i);
            System.out.println();
        }
    }
}

// 主程序创建线程对象，启动线程
public class Main6 {
    public static void main(String[] args) {
        // 3. 创建线程对象
        Thread t1 = new Mythread();
        // 4. 启动线程
        t1.start();

        Thread t2 = new Mythread();
        t2.start();

        // 不能为run()，否则当前线程对象始终为main
    //    t1.run();
    }
}
```

##### ② 常用方法
* start()：启动线程，调用 `start()` 后线程进入就绪状态（待 CPU 调度）。
* run()：线程执行的任务，`run()` 方法需要被重写。
* sleep(long millis)：使线程暂停指定的时间（毫秒）。
* join()：等待线程执行完毕，当前线程会等待调用它的线程执行完成后再继续执行。
* setPriority(int priority)：设置线程优先级。
* getName()：获取线程名称。

##### ③ 优缺点
* **优点**：代码编写简单，直接通过 this 即可获取当前线程。  
* **缺点**：Java 是单继承机制，继承了 Thread 就不能再继承其他类，灵活性差。

#### 2.4.2 实现 `Runnable` 接口

与继承 `Thread` 类不同，`Runnable` 接口提供了更大的灵活性。实现 `Runnable` 接口的类并重写 `run()` 方法。通过 `Thread` 类的构造方法，将 `Runnable` 对象传入，启动线程。

##### ① 使用步骤  
1️⃣ 创建一个实现 `Runnable` 接口的线程类。  
2️⃣ 实现 `run()` 方法定义线程任务。  
3️⃣ 创建自定义的实现了`Runnable`接口的线程类对象
4️⃣ 创建 `Thread` 对象，并将 `Runnable` 对象作为参数传入。    
5️⃣ 调用 `start()` 启动线程。
```java
// 1. 创建一个实现 Runnable 接口的线程类
class MyRunnable implements Runnable {
    // 2.实现 `run()` 方法定义线程任务
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName());
            System.out.println("i = " + i);
        }
    }
}

public class Main {
    public static void main(String[] args) {
        // 3. 创建自定义的实现了`Runnable`接口的线程类对象
        MyRunnable myRunnable = new MyRunnable();
        // 4. 创建 `Thread` 对象，并将 `Runnable` 对象作为参数传入
        Thread t1 = new Thread(myRunnable);
        // 5. 调用 `start()` 启动线程。
        t1.start();

        Thread t2 = new Thread(myRunnable);
        t2.start();
    }
}
```

##### ② 实现 `Runnable`   接口    VS  继承 `Thread` 类
| 特性        | 继承 `Thread` 类          |     |
| --------- | ---------------------- | ------------------- |
| **继承**    | 只能继承 `Thread` 类（单继承限制） | 可以继承其他类，并且可以实现多个接口  |
| **任务和线程** | 任务和线程绑定在同一个类中          | 任务和线程分离，任务可以由多个线程共享 |
| **性能**    | 适用于简单场景                | 性能稍好，适用于线程池等场景      |
| **线程池**   | 不适合与线程池配合使用            | 与线程池配合使用更为方便，适合高并发场景        |
| **灵活性**   | 不太灵活                   | 任务和线程可以解耦，多个线程共享任务  |

#### 2.4.3 实现 `Callable` 接口 + `Future` 接口

`Callable` 和 `Future` 接口常与线程池（`ExecutorService`）结合使用，它们提供了比 `Runnable` 更强大的功能，特别是在任务有返回值的场景。

##### ① 使用步骤
1️⃣ 创建一个实现 `Callable` 接口的任务类，里面实现 `call()` 方法。  
2️⃣ 使用 `ExecutorService` 提交 `Callable` 任务。  
3️⃣ 通过 `Future` 对象获取任务的执行结果或状态。

```java 
 // 1. 创建一个实现 `Callable` 接口的任务类，里面实现 `call()` 方法。  
class FactorialTask implements Callable<Long> {
    private long n;

    public FactorialTask(long n) {
        this.n = n;
    }

    // 实现 call() 方法
    @Override
    public Long call() {
        long result = 1;
        for (long i = 1; i <= n; i++) {
            result *= i;
        }
        return result;
    }
}

public class Main6 {
    public static void main(String[] args) {
        // 创建一个线程池
        ExecutorService executor = Executors.newFixedThreadPool(5);

        // 创建任务
        FactorialTask task1 = new FactorialTask(5);
        FactorialTask task2 = new FactorialTask(10);

        // 提交任务获取Future对象
        Future<Long> future1 = executor.submit(task1);
        Future<Long> future2 = executor.submit(task2);



        // 获取任务结果
        try {
            long result1 = future1.get();
            long result2 = future2.get();

            System.out.println("Result1: " + result1);
            System.out.println("Result2: " + result2);
        } catch (ExecutionException | InterruptedException e) {
            throw new RuntimeException(e);
        }
    }
}
```
或者
```java
public static void main(String[] args) {
    // 1. 创建一个 Callable 实现类（使用 Lambda 表达式）
    Callable<Integer> task = () -> {
        System.out.println("子线程正在计算...");
        Thread.sleep(2000); // 模拟耗时操作
        return 100 + 200;
    };

    // 2. 使用 FutureTask 包装 Callable
    FutureTask<Integer> futureTask = new FutureTask<>(task);

    // 3. 将 FutureTask 交给 Thread 执行
    Thread thread = new Thread(futureTask);
    thread.start();

    System.out.println("主线程继续做其他事情...");

    try {
        // 4. 获取结果。注意：get() 方法会阻塞主线程，直到子线程执行完毕
        Integer result = futureTask.get();
        System.out.println("计算结果为: " + result);
    } catch (InterruptedException | ExecutionException e) {
        e.printStackTrace();
    }
}
```
##### ② 常用方法
* **call()**：`Callable` 的任务方法，与 `run()` 不同，`call()` 能返回值。
* **cancel()**：取消任务执行。
* **get()**：获取任务的执行结果。
* **get(long timeout, TimeUnit unit)**：指定时间内未完成会抛出 `TimeoutException`。
* **isDone()**：判断任务是否完成。
* **isCancelled()**：判断任务是否被取消。

#### 2.4.4 使用 `Executor` 框架创建线程池

`Executor` 框架通过线程池来管理线程，避免了直接创建和销毁线程的麻烦。`ExecutorService` 提供了更高效的线程管理。

##### ① 使用步骤

1️⃣ 创建 `ExecutorService` 线程池。  
2️⃣ 提交任务（`Runnable` 或 `Callable`）到线程池。  
3️⃣ 管理线程池的生命周期，如关闭线程池等。  

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + " is running");
    }
}

public class Main {
    public static void main(String[] args) {
        ExecutorService executorService = Executors.newFixedThreadPool(2);  // 创建线程池
        
        executorService.submit(new MyRunnable());  // 提交任务
        executorService.submit(new MyRunnable());
        
        executorService.shutdown();  // 关闭线程池
    }
}
```


### 2.5 线程池

在 Java 并发编程中，线程池（ThreadPool） 是管理线程的最佳实践。它通过“池化技术”避免了频繁创建和销毁线程带来的性能开销，同时能够有效控制系统中并发线程的数量。

#### 2.5.1 线程池  VS  手动new Thread()
| **对比维度** | **`new Thread()` (手动创建)**       | **线程池 (`ExecutorService`)**  |
| -------- | ------------------------------- | ---------------------------- |
| **资源消耗** | 高。每次请求都要创建新对象，销毁旧对象，浪费内存和 CPU。  | 低。核心线程可以复用，避免频繁创建/销毁带来的系统开销。 |
| **响应速度** | 慢。任务必须等待线程创建完成后才能开始执行。          | 快。任务到达时，直接利用已存在的闲置线程执行。      |
| **线程管理** | 无。无法控制总数，容易因创建过多线程导致 OOM 或系统宕机。 | 强。可控制最大并发数，支持任务排队、定时执行和监控。   |
| **生命周期** | 短。任务跑完线程就销毁，属于一次性消耗品。           | 可配置。线程可以常驻，也可以根据闲置时间动态销毁。    |
| **功能扩展** | 单一。只有基本的 `start()` 方法。          | 丰富。提供定时执行、周期执行、任务拒绝策略等功能。    |

#### 2.5.2 7大核心参数 (ThreadPoolExecutor)
```java 
public ThreadPoolExecutor(
    int corePoolSize,                     // 1. 核心线程数。即使没有任务，这些线程也不会被销毁。
    int maximumPoolSize,                  // 2. 最大线程数。线程池允许的最大线程数。
    long keepAliveTime,                   // 3. 临时线程存活时间。非核心线程（临时线程）闲置时的存活时间。
    TimeUnit unit,                        // 4. 时间单位。存活时间的时间单位。
    BlockingQueue<Runnable> workQueue,    // 5. 任务队列。存放待执行任务的阻塞队列。
    ThreadFactory threadFactory,          // 6. 线程工厂。用于创建线程的工厂，通常用来给线程起个好听的名字。
    RejectedExecutionHandler handler      // 7. 拒绝策略。当队列和线程都满了，该如何处理新来的任务。
)

```
#### 2.5.3 工作流程

1️⃣ 线程池初始化，创建 **核心线程数** 个线程。  
2️⃣ 若提交的任务数量超过了核心线程数，线程池会将任务放入队列。  
3️⃣ 若队列已满且当前线程数还未达到 **最大线程数**，则新建线程来执行任务。  
4️⃣ 若队列已满且当前线程数已达到 **最大线程数**，则执行拒绝策略。  
5️⃣ 非核心线程在空闲超过 **空闲线程存活时间** 后会被销毁。  

```java 
public class ThreadPoolDemo {
    public static void main(String[] args) {
        // 1. 手动创建线程池
        ExecutorService executor = new ThreadPoolExecutor(
            2,                      // corePoolSize: 核心员工数（常驻线程）
            5,                      // maximumPoolSize: 最大员工数（包含临时工）
            60L,                    // keepAliveTime: 临时工闲置多久被开除
            TimeUnit.SECONDS,       // unit: 时间单位
            new LinkedBlockingQueue<>(3), // workQueue: 任务排队用的“休息室”（容量为3）
            Executors.defaultThreadFactory(), // threadFactory: 招聘员工的方式
            new ThreadPoolExecutor.CallerRunsPolicy() // handler: 任务太多的拒绝策略
        );

        // 2. 提交任务
        for (int i = 1; i <= 10; i++) {
            final int taskId = i;
            executor.execute(() -> {
                System.out.println(Thread.currentThread().getName() + " 正在执行任务 " + taskId);
                try {
                    Thread.sleep(500); // 模拟业务处理
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }

        // 3. 关闭线程池（优雅停机）
        executor.shutdown();
    }
}
```

#### 2.5.4 拒绝策略
* **AbortPolicy (默认)**：直接抛出 RejectedExecutionException 异常，阻止系统运行。  
* **CallerRunsPolicy**：谁提交的任务谁执行（退回给调用者线程处理），这能减缓任务提交的速度。  
* **DiscardOldestPolicy**：丢弃队列中最老（排在最前面）的任务，尝试再次提交。  
* **DiscardPolicy**：直接丢弃任务，不予处理也不报错。  

#### 2.5.5 常见的几种线程池
| **线程池类型**                | **特点**                       | **潜在风险**                   |
| ------------------------ | ---------------------------- | -------------------------- |
| **FixedThreadPool**      | 固定数量的线程池。线程数固定，适用于处理大量短时间任务。 | 队列长度无限，可能导致内存耗尽（OOM）。      |
| **SingleThreadExecutor** | 只有一个线程，任务按顺序执行。              | 队列长度无限，任务积压时可能导致内存耗尽（OOM）。 |
| **CachedThreadPool**     | 线程数几乎无限，适用于处理大量短期异步任务。       | 创建过多线程，可能导致内存耗尽（OOM）。      |
| **ScheduledThreadPool**  | 支持定时任务或周期任务。                 | 线程数过多，可能导致系统资源耗尽。          |

##### ①newFixedThreadPool()

创建一个固定大小的线程池，线程数不会超出设定值，空闲线程会继续存在，直到显式关闭线程池。如果任务数量大于线程池容量，任务会被放入任务队列中等待执行。

```java
public static void main(String[] args) {
    ExecutorService executor = Executors.newFixedThreadPool(10);

    // 提交任务
    for (int i = 0; i < 15; i++) {
        final int taskId = i;
        executor.submit(() -> {
            System.out.println("执行任务: " + taskId + ", 线程: " +
                    Thread.currentThread().getName());
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        });
    }
    executor.shutdown();
}
```
