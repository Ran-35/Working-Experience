# Mybatis-Plus

MyBatis-Plus (MP for short) is an enhancement tool for MyBatis, adding enhancements without altering the core functionality of MyBatis. Its core philosophy is "born to simplify development and improve efficiency."

## 1. Basic Application

### 1.1 Adding Dependencies

⚠️ After adding mybatis-plus-boot-starter, there is no need to add the native mybatis-spring-boot-starter, otherwise conflicts may occur.

```xml
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-boot-starter</artifactId>
    <version>3.5.10</version> </dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
```

### 1.2 Configure the data source

🏷️ Configure the data source in src/main/resources/application.yml.

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/your_db?useSSL=false&serverTimezone=GMT%2B8
    username: root
    password: yourpassword

mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl # Enable SQL logging in the console (recommended for developers)
  mapper-locations: classpath*:/mapper/**/*.xml # Configuration is only required if there is a custom XML mapping file.
```

### 1.3 Defining Entity Classes

```java
@Data // Lombok annotation
@TableName("user") // The corresponding user table in the database
public class User {
    @TableId(type = IdType.AUTO) // Specify primary key and auto-increment strategy
    private Long id;
    private String name;
    private Integer age;
    private String email;
}
```

### 1.4 Defining the Mapper Interface

💡Core Functionality: Simply inherit from BaseMapper< T > to have complete CRUD capabilities without writing any SQL.

```java
@Mapper // Marked as a Mapper interface
public interface UserMapper extends BaseMapper<User> {
    // All CRUD methods are automatically inherited
}

```

### 1.5 SpringBoot Integration Scanning
#### 1.5.1 @Mapper Method

The `org.apache.ibatis.annotations.Mapper` annotation is added to each Mapper interface. MyBatis's auto-configuration class (MybatisPlusAutoConfiguration) will automatically scan and register these annotated interfaces.

```java
@Mapper
public interface UserMapper extends BaseMapper<User> {
}
```

#### 1.5.2 @MapperScan Method 

Using @MapperScan("com.example.mapper") on the startup class will automatically register all interfaces under this package as Mappers into the Spring container.
```java
@SpringBootApplication
@MapperScan("com.example.demo.mapper") // Scan your Mapper path
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

#### 1.5.3 Comparison

| **Solution** | **Operation** | **Result** |
| ------------ | ------------- | ---------- |
| **Solution A** | Add the `@MapperScan` annotation to the startup class, specifying the package path to scan. | Saves the trouble of writing annotations for each interface, suitable for projects with many interfaces, reducing duplicate code. |
| **Solution B** | Add the `@Mapper` annotation to each interface. | Suitable for cases with very few interfaces, avoiding configuration in the startup class, configuring directly on the interface. |

### 1.6 Condition Builder

🏷️ MP provides powerful condition builder, avoiding the need to manually write dynamic SQL.
```java 
// Search for users who are over 18 years old and whose names contain "Tom".
QueryWrapper<User> wrapper = new QueryWrapper<>();
wrapper.gt("age", 18)
       .like("name", "Tom");
       
List<User> list = userMapper.selectList(wrapper);
```

## 2. Advanced Applications
### 2.1 Pagination
#### 2.1.1 Configuring the Pagination Interceptor
```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // Add a pagination plugin to the interceptor (specify the database type, such as MySQL).
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```
⚠️ If the Mybatis version is lower than 3.4.0, PaginationInterceptor should be used.
```java 
@Configuration
public class MybatisPlusConfig {
    @Bean
    public PaginationInterceptor paginationInterceptor() {
        return new PaginationInterceptor();
    }
}
```

#### 2.1.2 Using Pagination

🎯 MP provides the IPage interface and Page implementation classes to hold paginated data.

```java
@Service
public class UserService {

    @Autowired
    private UserMapper userMapper;

    public IPage<User> getUserPage(int pageNum, int pageSize) {
        // 1. Create a pagination object: parameters are the current page number and the number of pages to display per page.
        Page<User> page = new Page<>(pageNum, pageSize);

        // 2. Execute paginated query
        // You can pass in LambdaQueryWrapper to add filter conditions.
        LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<>();
        queryWrapper.eq(User::getStatus, 1); 

        return userMapper.selectPage(page, queryWrapper);
    }
}
```
🏷️ The content returned by Ipage is:

| **Property**   | **Description**                                                                             |
| -------------- | ------------------------------------------------------------------------------------------- |
| `getRecords()` | The list of data for the current page (of type `List`).                                     |
| `getTotal()`   | The total number of records, representing the total count of records in the database.       |
| `getCurrent()` | The current page number, indicating the page being displayed.                               |
| `getSize()`    | The number of items displayed per page, indicating how many records are shown on each page. |
| `getPages()`   | The total number of pages, indicating how many pages the total records are divided into.    |


#### 2.1.3 Custom Pagination

💡 Simply pass a Page object as the first parameter to the method in the Mapper interface. You don't need to write a LIMIT statement in the XML; MP will automatically append it to the end of the SQL.
```java 
public interface UserMapper extends BaseMapper<User> {
    // MP will automatically perform pagination as long as the first parameter is IPage.
    IPage<UserVo> selectCustomPage(IPage<UserVo> page, @Param("name") String name);
}
```
```xml
<select id="selectCustomPage" resultType="UserVo">
    SELECT * FROM user WHERE name = #{name}
</select>
```

### 2.2 Dynamic Table Names

To implement operations on multiple database tables using a single entity class, you can use PaginationInterceptor (MP) to achieve dynamic table names.

#### 2.2.1 Configuring the Dynamic Table Name Interceptor

⚠️ If your Mybatis version is lower than 3.4.0, you should use PaginationInterceptor.
```java
@Configuration
public class MybatisPlusConfig {
    // Define ThreadLocal to store dynamic table names
    public static ThreadLocal<String> CUSTOM_TABLE_NAME = new ThreadLocal<>();

    @Bean
    @Order(0)
    public PaginationInterceptor paginationInterceptor() {
        PaginationInterceptor paginationInterceptor = new PaginationInterceptor();

        // --- Dynamic table name configuration starts ---
        List<ISqlParser> sqlParserList = new ArrayList<>();
        DynamicTableNameParser tableNameParser = new DynamicTableNameParser();

        tableNameParser.setTableNameHandlerMap(new HashMap<String, ITableNameHandler>(2) {{
            // When "user" is recognized in SQL, replace it with the value from ThreadLocal
            put("user", (metaObject, sql, tableName) -> {
                String dynamicName = CUSTOM_TABLE_NAME.get();
                return dynamicName != null ? dynamicName : tableName;
            });
        }});

        sqlParserList.add(tableNameParser);
        paginationInterceptor.setSqlParserList(sqlParserList);
        // --- Dynamic table name configuration ends ---
        return paginationInterceptor;
    }
}

```
⚠️ If Mybatis version is higher than 3.4.0, see below:

#### 2.2.2 Using ThreadLocal to Pass Variables

💡 To ensure thread safety, ThreadLocal is typically used to pass dynamic table name identifiers between the Service layer and the interceptor.

```java 
@Configuration
public class MybatisPlusConfig {
    // Use ThreadLocal to pass variables
    private static final ThreadLocal<String> TABLE_NAME_HOLDER = new ThreadLocal<>();

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        
        // Create dynamic table name plugin
        DynamicTableNameInnerInterceptor dynamicTableNameInnerInterceptor = new DynamicTableNameInnerInterceptor();
        
        dynamicTableNameInnerInterceptor.setTableNameHandler((sql, tableName) -> {
            // tableName is the original table name (defined by @TableName in the entity class)
            // We can use ThreadLocal to get the "suffix" or "specific name" passed at runtime
            String dynamicSuffix = TableNameContext.get(); 
            
            if ("user".equals(tableName) && dynamicSuffix != null) {
                return tableName + "_" + dynamicSuffix; // Return the actual table name to execute: user_2024
            }
            return tableName; // Otherwise, return the original table name
        });

        // Add the plugin to the main interceptor (recommended to place before the pagination plugin)
        interceptor.addInnerInterceptor(dynamicTableNameInnerInterceptor);
        return interceptor;
    }
}

```
#### 2.2.3 Use dynamic table names
```java 
@Service
public class UserService {
    @Autowired
    private UserMapper userMapper;

    public List<User> getUserFromSpecificTable(String year) {
        try {
            // Set the table suffix for the current thread to query
            MybatisPlusConfig.TABLE_NAME_HOLDER.set(year);
            
            // Execute the query; at this point, the SQL will automatically change to: SELECT * FROM user_2024
            return userMapper.selectList(null);
        } finally {
            // It's necessary to clear the ThreadLocal to avoid affecting subsequent threads
            TableNameContext.remove();
        }
    }
}

```
